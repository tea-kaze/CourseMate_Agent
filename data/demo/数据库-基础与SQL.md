# 数据库：基础与 SQL（演示资料）

## 1. 数据库基本概念

数据库（DB）是按照数据结构组织、存储和管理数据的仓库；数据库管理系统（DBMS）是位于用户与操作系统之间、负责数据定义、操纵、控制与维护的软件系统，例如 MySQL、PostgreSQL、SQLite。数据库系统（DBS）由数据库、DBMS、应用程序和数据库管理员共同构成。

关系模型用二维表组织数据：表称为关系，行称为元组，列称为属性。主键用于唯一标识一行记录；外键引用另一张表的主键，用来建立表与表之间的联系。关系完整性约束包括：

- 实体完整性：主键不能为空且取值唯一；
- 参照完整性：外键的取值必须是被引用表的主键值或为空；
- 用户定义完整性：满足业务规则的约束（如年龄不能为负、成绩在 0~100 之间）。

## 2. 关系代数与 SQL

关系代数的基本运算：选择（σ，按条件筛选行）、投影（π，选取指定列）、连接（⋈，按连接条件合并两张表）、并、差和笛卡尔积。SQL 是关系代数的高级实现，按功能分为四类：

- DDL 数据定义语言：CREATE / ALTER / DROP；
- DML 数据操纵语言：INSERT / UPDATE / DELETE；
- DQL 数据查询语言：SELECT；
- DCL 数据控制语言：GRANT / REVOKE。

建表与增删改示例：

```sql
CREATE TABLE student (
  id INTEGER PRIMARY KEY,
  name VARCHAR(50) NOT NULL,
  age INTEGER CHECK (age >= 0)
);
INSERT INTO student (id, name, age) VALUES (1, '张三', 20);
UPDATE student SET age = 21 WHERE id = 1;
DELETE FROM student WHERE id = 1;
```

查询要点：WHERE 过滤行；GROUP BY 分组；聚合函数 COUNT、SUM、AVG、MAX、MIN 对每组统计；HAVING 过滤分组后的结果，而 WHERE 中不能使用聚合函数；ORDER BY 排序。JOIN 用于连接多表，INNER JOIN 只返回匹配的行，LEFT JOIN 保留左表全部行。

```sql
SELECT c.name, COUNT(s.id) AS student_count
FROM course c
LEFT JOIN student s ON c.id = s.course_id
GROUP BY c.name
HAVING COUNT(s.id) > 0
ORDER BY student_count DESC;
```

## 3. 数据库设计规范化

函数依赖：若 X 的值确定后 Y 的值也唯一确定，则称 Y 函数依赖于 X（记作 X → Y）。主键对非主属性的依赖分为完全依赖、部分依赖和传递依赖。规范化就是通过拆分表消除数据冗余与异常（插入异常、更新异常、删除异常）的过程：

- 第一范式（1NF）：每一列都是不可再分的原子值；
- 第二范式（2NF）：满足 1NF，且每个非主属性完全依赖于主键（消除部分依赖）；
- 第三范式（3NF）：满足 2NF，且非主属性不传递依赖于主键；
- BCNF：主属性之间也不允许存在部分或传递依赖，是 3NF 的加强形式。

示例：订单明细表（订单号、商品号、商品名、数量）中，“商品名”只依赖于商品号，属于部分依赖，应拆分为订单明细表和商品表。实际工程中常根据查询需求适当反规范化（保留冗余列）换取查询性能。

## 4. 事务与并发控制

事务是数据库操作的最小执行单元，具有 ACID 特性：

- 原子性（Atomicity）：事务内操作要么全部成功，要么全部回滚；
- 一致性（Consistency）：事务执行前后数据库都处于一致状态；
- 隔离性（Isolation）：并发事务之间互不干扰，由锁与隔离级别保证；
- 持久性（Durability）：事务提交后结果永久保存，由日志恢复机制保证。

并发事务可能产生三类问题：脏读（读到其他事务未提交的数据）、不可重复读（同一行两次读取结果不同）、幻读（两次查询得到的结果集行数不同）。SQL 标准定义了四个隔离级别：

- 读未提交：可能发生脏读、不可重复读、幻读；
- 读已提交：避免脏读，仍可能发生不可重复读和幻读；
- 可重复读：避免脏读与不可重复读，仍可能幻读（MySQL 默认级别，InnoDB 通过间隙锁基本消除幻读）；
- 串行化：事务完全串行执行，隔离性最强但并发性能最差。

锁机制：共享锁（读锁，可多个事务并发读）与排他锁（写锁，互斥）。多个事务互相持有对方需要的锁且互不释放时产生死锁，数据库通过锁超时或死锁检测（如 InnoDB 回滚代价最小的事务）来解除。

## 5. 索引与查询优化

索引是加快查询的数据结构，常用 B+ 树（范围查询高效、节点扇出大）与哈希索引（等值查询快，但不支持范围查询）。聚簇索引决定数据的物理存储顺序（InnoDB 中即主键索引），非聚簇索引的叶子节点存储主键值，查询时需要回表。

- 优点：加速查询、支持唯一约束；
- 缺点：占用额外存储空间，增删改时需要同步维护索引，写入变慢。

使用要点：为高频查询列建立索引；遵循最左前缀原则（联合索引 (a, b, c) 可命中 a、a,b、a,b,c 三种查询）；避免在索引列上做函数运算或隐式类型转换，否则索引失效；使用覆盖索引减少回表。优化手段：用 EXPLAIN 分析执行计划、定位慢查询、避免 SELECT *、按需分页。
